The case

Why run models locally?

🔒

Privacy

  • Your prompts & data stay on-device
  • Nothing logged, cached, or used for training
💸

Cost

  • Flat, predictable cost
  • No per-token charges, free forever
🛰️

Offline & always on

  • Works with no internet
  • No rate limits, outages, or third parties
🎛️

Control

  • Pick model, quantization & settings
  • Fine-tune, swap, or train your own
  • Run uncensored models or special configurations

Reality check

What does “local” actually need?

The model parameters (weights) must fit in your RAM (VRAM or unified memory).

Model sizeWhat it means for you
1–4B Usable for very specific tasks only
4–14B Can produce coherent results, but YMMV
14–70B Very useful if you know how to use it
70B+ Needs dedicated hardware

The decision

Which model should you pick?

  • Bigger is better: pick the largest model you can, with the best benchmarks.
  • Benchmaxxing exists: but it’s not that bad.
  • Prefer a MoE model (mixture of experts) over a dense one; only some parameters are active for each token, so inference is much faster.
  • They move fast: “which one to pick” changes about every month

Tricks

Quantization: shrink without losing much

  • Models are born at 16-bit precision
  • At 16-bit: B parameters * 2 = GB vRAM needed (+ some overhead)
  • Quantization stores weights in fewer bits
  • Cuts memory dramatically while quality stays surprisingly close
16-bit

Full

  • ~16 GB for an 8B
  • Reference quality
8-bit

Q8

  • ~8 GB
  • Near-lossless
4-bit

Q4

  • ~4 GB
  • Quality trade-off
2-bit

Q2

  • ~2 GB
  • Heavily compressed, noticeably degraded
🎯

Practical advice: default to 8-bit (Q8 / FP8) quants.

Hardware

Hardware options

Three ways to host models, in order of affordability.

Most affordable
🎮

Consumer GPUs

  • NVIDIA, AMD, Intel
  • ~8–16 GB VRAM
  • Fast for small mid models, buy used
Middle ground
⚙️

Unified memory

  • Apple MacBooks, NVIDIA DGX Spark
  • Large, fast shared memory
  • Runs bigger models in one box
Most expensive
🧠

Workstation GPUs

  • e.g. RTX 6000 Pro
  • Lots of VRAM, pricey
  • Heaviest local setups, multi-GPU
💡

What matters: VRAM capacity and memory bandwidth

Hands-on

From zero to hero with ollama

# 1 · install Ollama
curl -fsSL https://ollama.com/install.sh | sh

# 2 · pull a model
ollama pull qwen3.6:latest

# 3 · chat right away
ollama run qwen3.6:latest

# 4 · it's also an API
curl http://localhost:11434/api/chat -d '{"model":"qwen3.6:latest","stream":false}'

Now what?

You’ve got a model running

  • You’re set: hardware + a model running locally
  • That means you got a local OpenAPI-compatible HTTP API server
  • Now you need tooling: a harness or integration to actually use it
  • My favorites: Claude Code & Open WebUI
🔌

It’s just an API. Anything that speaks the OpenAI protocol can point at your local model: CLIs, chat UIs, editors, home automation.
